# Security and privacy review (Phase 4)

**Scope:** the public repository at `main`
(`dd8064ac6e3ebf505acb23fa01f5da051e07747f`), tracked files, documentation and
the Phase 4 documentation changes. Production secrets and security settings were
**not** modified during this review.

A pattern-based scan is not proof that secrets are absent. This document records
exactly what was checked, what was found, and what remains unverified.

## Checks performed

### 1. Tracked-file pattern scan (2026-11-10)

A local scan read all **232 tracked files** (files over 2 MB skipped) and matched:

| Pattern class | Result |
|---|---|
| Clerk secret keys (`sk_test_…` / `sk_live_…`) | 0 matches |
| GitHub tokens (`ghp_…`, `gho_…`, `ghs_…`, `ghu_…`, `ghr_…`, `github_pat_…`) | 1 match (synthetic fixture) |
| AWS access keys (`AKIA…`) | 0 matches |
| Private key blocks (`-----BEGIN … PRIVATE KEY-----`) | 0 matches |
| Neon tokens (`npg_…`) | 0 matches |
| JWTs (three-part `eyJ…`) | 0 matches |
| PostgreSQL URLs with embedded credentials | 5 matches (synthetic fixtures) |
| Render deploy hooks (`api.render.com/deploy/srv-…`) | 5 matches (synthetic fixtures) |
| Hard-coded Windows user paths | 0 matches |
| Suspicious filenames (`.env`, `*.pem`, `*.key`, `secrets/`, `id_rsa`) | 0 matches |

### 3. Ignored and local files

- `.env`, `.env.*` (except `.env.example`), `secrets/`, `*.pem`, `*.key`,
  `.neon`, `node_modules/`, build output and private benchmark directories are
  git-ignored.
- `.env.local` is confirmed ignored by `.gitignore` and was not tracked.
- `neon.ts` is tracked but contains only boilerplate `@neon/config` branch policy
  with no credentials.

### 4. History spot-check

- A history search for key-shaped `sk_test_`/`sk_live_` strings (12+ characters)
  returned no commits and no files at `dd8064a`.
- Commits matched only the literal documentation phrase `sk_test_…` used to
  explain the masked-secret incident; that is prose, not a credential.
- One earlier promotion run failed because a masked Clerk key containing U+2026
  ellipsis characters had been stored; the fix removed it. The value was never
  committed.

### 5. Documentation and provenance accuracy

- README distinguishes **synthetic demo catalogue**, **user imports** and
  **private benchmark material**, and states the demo is derived from aggregate
  summaries, not generated by BenchScope.
- Hosted mode is documented as never mounting benchmark routes; the production
  capabilities endpoint returns `{"enabled":false}`.
- Hosted observability is explicitly **not** claimed; telemetry evidence is
  labelled local.
- AI repair is labelled **supervised**, not autonomous production recovery.
- Rollback is labelled an application-revision rehearsal, not a database
  restore.

### 6. Workflow permissions

- `ci.yml` and `promote-production.yml` use read-only `contents`/`actions`
  permissions except where a deploy requires Pages or environment access.
- Production secrets are environment-scoped and only released after the
  protected `production` environment approval.
- No workflow prints tokens; `generate_smoke_tokens.py` writes to `GITHUB_ENV`
  only.

## Findings

| # | Severity | Finding | Status |
|---|---|---|---|
| 1 | Info | All credential-shaped matches are synthetic test fixtures | Accepted, documented |
| 2 | Info | Production GitHub environment allows self-review (`prevent_self_review=false`) | Accepted limitation; owner is sole reviewer |
| 3 | Info | Main ruleset requires **0 approving reviews**, so independent code review is procedural | Accepted limitation |
| 4 | Low | Repair worker is host-supervised, not OS-isolated, and may use the operator's GitHub CLI credentials | Documented; worker not hosted and disabled by default |
| 5 | Low | `.env` generation in `scripts/start.py` creates a local throwaway password | Local-only, ignored, not committed |
| 6 | Info | Historical evidence branches still carry the pre-#65 verifier | Documented in Phase 3C; not used as authoritative |

No critical or high-severity secret exposure was found.

## What this review does **not** establish

- It does not prove that no secret exists anywhere in history, forks, releases,
  issues, Actions logs or provider dashboards. Only tracked files at `main` and a
  limited history search were checked.
- It does not audit the live Clerk, Neon or Render accounts.
- It does not verify GitHub organisation-level permissions, branch rulesets on
  other branches, or installed apps.
- It does not scan binary blobs, images or large files over 2 MB.
- It does not replace a credentialed secret-scanning service.
